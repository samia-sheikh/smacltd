## SLIDE 12: Authentication & Security

### Enterprise-Grade Security

**Authentication Methods:**
- Email + Password (with strict validation)
- Google OAuth 2.0 (one-click sign-in/sign-up)
- JWT token-based session management

**Security Features:**
- Password rules: 8-16 chars, uppercase, number, special character
- Email verification required for account activation
- Forgot/reset password flow via email link
- Auto-logout on 401 (expired/invalid token)
- Role-based access control (User vs Admin permissions)
- Protected routes prevent unauthorized page access
- Token persisted to localStorage (survives refresh)
- Socket.IO authenticated with JWT token

**Route Protection:**
```
Public:     /signin, /signup, /about-us, /blogs, /privacy-policy
Auth-only:  /feed, /messaging, /courses, /market, /services
Admin-only: /admin/dashboard (permission: "admin.dashboard")
```

> **Speaker Notes:** "Security is built into every layer. We support both email/password and Google OAuth authentication. Passwords require uppercase, numbers, and special characters. Every account must verify their email before activation. Sessions use JWT tokens that persist across browser refreshes via Redux Persist. All API calls include the Bearer token, and any 401 response automatically logs the user out. Routes are protected at three levels: public pages anyone can see, authenticated pages requiring login, and admin pages requiring the admin role. Even the WebSocket connection is authenticated with the JWT token."

## 2.1 Social Feed - Technical Deep Dive

**Architecture:**
- The feed uses a masonry grid layout that responsively adjusts from 3 columns (desktop) to 2 (tablet) to 1 (mobile)
- Infinite scroll is implemented via a custom `useInfiniteScroll` hook with 500ms debounce
- Each scroll event checks if the user is within 1000px of the page bottom
- Posts load in batches of 6 (GET /api/user/post?limit=6&page=X)
- Duplicate posts are automatically filtered by postId

**Post Interactions:**
- Likes: Toggle via POST /api/user/post/like -- heart color randomizes from theme palette (blue, pink, red, yellow, black)
- Comments: Open in a scrollable modal with sticky header/footer -- validated at max 255 chars
- Shares: UI built with user search, but backend not yet wired
- Follow: Three-state system (Not Following -> Pending -> Accepted) with request-based approval

**Stories:**
- Instagram-style stories with auto-advancing progress bar
- Create stories by uploading images (POST /api/user/story)
- View own stories with viewer count + delete option
- View others' stories with reply-to-story input
- Stories fetched from followed users (GET /api/user/story)
- Displayed in a horizontal slider (react-slick, 6/3/2/1 slides responsive)

**First-Time User Onboarding:**
- When a new user has no preferences, a 3-step wizard appears:
  1. Language & Country selection
  2. Gender selection
  3. Interest selection (scrollable grid with teal border on selected)
- Data submitted to POST /api/user/add-details
- Feed then personalizes based on selected interests

## 2.5 Authentication - Deep Dive

**Sign-In Flow (Email):**
1. Formik form with Yup validation (email format, password 8-16 chars)
2. POST /api/auth/user/login { email, password }
3. Server returns { user, token }
4. Redux dispatch: setUserAuth({ user, token })
5. Token persisted to localStorage via Redux Persist
6. Socket.IO connects with token
7. Navigate to /feed

**Sign-In Flow (Google):**
1. useGoogleLogin() opens Google consent screen
2. Google returns access_token
3. POST /api/auth/user/login/google { accessToken }
4. Backend exchanges Google token, creates/finds user, returns JWT
5. Same Redux + Socket + Navigate flow as email

**Sign-Up Flow:**
1. Stricter validation (3-16 char names, letters only, password: uppercase + number + special char)
2. POST /api/auth/user/register-user
3. Server creates account + sends verification email
4. Verification modal shown -> user clicks link in email
5. GET /api/auth/user/verify-email?jwt={token}
6. Account activated -> user can sign in

**Password Reset:**
1. User enters email on /password page
2. PATCH /api/user/forgot-password { email }
3. Server sends reset link: /new-password?jwt={resetToken}
4. User sets new password (with confirmation)
5. PATCH /api/user/setnew-password with reset token in Authorization header
